## ЭТАП 4: Специфика исламского образования (6-8 недель)

**Цель:** Уникальные фичи для исламского образования, которых нет у конкурентов.

### Приоритет 4.1: Родительский кабинет

**Проблема:** Многие студенты - дети. Родители платят за обучение и хотят видеть прогресс.

#### 4.1.1 Модели данных

```prisma
model ParentChildLink {
  id          String   @id @default(uuid())
  parentId    String
  parent      User     @relation("ParentLinks", fields: [parentId], references: [id], onDelete: Cascade)

  childId     String
  child       User     @relation("ChildLinks", fields: [childId], references: [id], onDelete: Cascade)

  relationship String  @default("parent")  // parent, guardian, etc.

  canViewProgress    Boolean @default(true)
  canViewGrades      Boolean @default(true)
  canReceiveReports  Boolean @default(true)

  createdAt   DateTime @default(now())

  @@unique([parentId, childId])
}
```

#### 4.1.2 Функционал

**Связывание родитель-ребенок:**
- Учитель или админ может связать аккаунты
- Родитель получает инвайт-ссылку для подтверждения
- Ребенок (если достаточно взрослый) может одобрить связь

**Родительский dashboard (`/parent`):**
- Список детей с карточками
- Для каждого ребенка:
  - Текущие потоки и курсы
  - Прогресс прохождения (%)
  - Последняя активность
  - Посещаемость уроков
  - Оценки за тесты и ДЗ
  - Комментарии учителей

**Уведомления для родителей:**
- Ребенок пропустил урок
- Низкая оценка за тест
- Не сдано ДЗ в срок
- Достижение (положительное событие)
- Еженедельный отчет о прогрессе

**Ограничения доступа:**
- Родитель видит только данные своих детей (read-only)
- Не может писать в чат от имени ребенка
- Не может изменять настройки аккаунта ребенка
- Может связаться с учителем через отдельный канал

#### 4.1.3 API

- `GET /api/parent/children` - список детей
- `GET /api/parent/children/[childId]/progress` - прогресс ребенка
- `GET /api/parent/children/[childId]/attendance` - посещаемость
- `GET /api/parent/children/[childId]/grades` - оценки
- `POST /api/parent/link-request` - запрос на связывание
- `POST /api/student/approve-parent-link` - одобрить связь (со стороны ребенка)

### Приоритет 4.2: Инструменты для изучения Корана

**Цель:** Специализированные инструменты для хифза (заучивания) и таджвида.

#### 4.2.1 Tajweed визуализация

**Что это:** Цветовая разметка текста Корана для правил таджвида.

**Реализация:**
- Использовать готовую библиотеку (например, Quran.com API)
- Или создать собственную разметку на основе правил
- Цвета: красный (идгам), зеленый (гунна), синий (калькаля), и т.д.

**Модели данных:**

```prisma
model QuranVerse {
  id          String   @id @default(uuid())
  surahNumber Int
  verseNumber Int
  arabicText  String   @db.Text
  transliteration String? @db.Text
  translation String?  @db.Text  // русский перевод

  tajweedData Json?    // разметка для tajweed правил

  @@unique([surahNumber, verseNumber])
}

model MemorizationProgress {
  id          String   @id @default(uuid())
  userId      String
  user        User     @relation(fields: [userId], references: [id], onDelete: Cascade)

  surahNumber Int
  verseNumber Int

  status      MemorizationStatus @default(LEARNING)

  lastReviewed DateTime?
  nextReview   DateTime?  // для spaced repetition
  reviewCount  Int       @default(0)

  confidence   Int       @default(0)  // 0-100

  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  @@unique([userId, surahNumber, verseNumber])
}

enum MemorizationStatus {
  LEARNING    // учу сейчас
  MEMORIZED   // выучил
  REVIEWING   // повторяю
  FORGOTTEN   // забыл, нужно повторить
}
```

#### 4.2.2 Spaced Repetition для хифза

**Алгоритм:** SM-2 (SuperMemo) или упрощенная версия.

**Принцип:**
- Студент отмечает аят как "выучен"
- Система планирует повторения: через 1 день, 3 дня, 7 дней, 14 дней, 30 дней
- Если студент забыл → интервал сбрасывается
- Если помнит → интервал увеличивается

**UI:**
- Страница "Мой хифз" (`/student/memorization`)
- Список сур с прогрессом
- Календарь повторений: "Сегодня нужно повторить 5 аятов"
- Карточки для повторения (показать аят, студент читает, отмечает "помню"/"забыл")

**Функционал:**
- Выбор суры и аятов для заучивания
- Аудио прослушивание (интеграция с Quran.com API или локальные файлы)
- Запись своего чтения (голосовой ответ)
- Учитель может проверить запись и дать обратную связь
- Статистика: сколько аятов выучено, процент от Корана

#### 4.2.3 API

- `GET /api/quran/surahs` - список сур
- `GET /api/quran/verses` - аяты суры с tajweed разметкой
- `GET /api/memorization/progress` - мой прогресс заучивания
- `POST /api/memorization/mark-learned` - отметить аят как выученный
- `POST /api/memorization/review` - результат повторения
- `GET /api/memorization/due-today` - что нужно повторить сегодня

### Приоритет 4.4: Ijazah система (опционально)

**Что это:** Цепочка передачи знаний в исламском образовании. Важно для традиционных курсов.

**Концепция:**
- Учитель имеет иджазу (разрешение) от своего учителя
- Студент, завершивший курс, получает иджазу от учителя
- Формируется цепочка: Пророк → сподвижники → ... → современный учитель → студент

#### 4.4.1 Модели данных

```prisma
model Ijazah {
  id          String   @id @default(uuid())

  issuerId    String
  issuer      User     @relation("IssuedIjazahs", fields: [issuerId], references: [id])

  recipientId String
  recipient   User     @relation("ReceivedIjazahs", fields: [recipientId], references: [id])

  courseId    String?
  course      Course?  @relation(fields: [courseId], references: [id])

  subject     String   // например "Таджвид", "Хифз Корана"
  description String?  @db.Text

  chainOfTransmission Json?  // массив имен в цепочке

  issuedAt    DateTime @default(now())

  certificateUrl String?  // PDF сертификата иджазы
}
```

#### 4.4.2 Функционал

**Для учителя:**
- Указать свою цепочку передачи при создании профиля
- Выдать иджазу студенту после завершения курса
- Просмотр всех выданных иджаз

**Для студента:**
- Просмотр полученных иджаз
- Отображение полной цепочки передачи
- Публичная страница с верификацией иджазы

**Сертификат иджазы:**
- Отличается от обычного сертификата
- Включает полную цепочку передачи
- Более торжественный дизайн
- Арабский текст с переводом

## ЭТАП 5: AI и автоматизация (8-12 недель)

**Цель:** Снизить нагрузку на учителей, улучшить качество обучения через AI.

### Приоритет 5.1: AI для учителя

#### 5.1.1 Автогенерация тестов

**Технология:** GPT-4 или Claude API

**Процесс:**
1. Учитель загружает текст урока или указывает тему
2. AI генерирует вопросы множественного выбора
3. Учитель проверяет и редактирует вопросы
4. Сохранение в библиотеку вопросов

**Промпт для AI:**
```
Создай 5 вопросов множественного выбора по следующему тексту урока:
[текст урока]

Требования:
- 4 варианта ответа на каждый вопрос
- Только один правильный ответ
- Вопросы должны проверять понимание, а не просто память
- Уровень сложности: [начальный/средний/продвинутый]
```

**API:**
- `POST /api/ai/generate-quiz` - генерация теста из текста

#### 5.1.2 Автопроверка голосовых ответов

**Технология:** Whisper API (OpenAI) для транскрипции

**Процесс:**
1. Студент записывает голосовой ответ
2. Аудио отправляется в Whisper API
3. Получаем текстовую транскрипцию
4. Сравниваем с правильным ответом (текстовое сравнение)
5. Если совпадение >80% → автоматически PASSED
6. Если <80% → отправляется учителю на ручную проверку

**Ограничения:**
- Работает только для вопросов с четким правильным ответом
- Для таджвида и чтения Корана нужна ручная проверка учителем

**API:**
- `POST /api/ai/transcribe-audio` - транскрипция аудио
- `POST /api/ai/check-voice-answer` - автопроверка голосового ответа

#### 5.1.3 Аналитика и рекомендации

**AI анализирует данные студентов:**
- Кто отстает по прогрессу
- Кто пропускает уроки регулярно
- Кто плохо справляется с тестами
- Какие темы вызывают сложности у группы

**Рекомендации для учителя:**
- "Студент Али пропустил 3 урока подряд - свяжитесь с ним"
- "70% группы не справились с тестом по теме X - возможно, нужно повторить"
- "Студентка Фатима показывает отличные результаты - рассмотрите перевод в продвинутую группу"

**Dashboard учителя:**
- Вкладка "AI Insights" с рекомендациями
- Приоритизация: срочные → важные → информационные

### Приоритет 5.2: AI для студента

#### 5.2.1 Чат-бот помощник

**Технология:** RAG (Retrieval-Augmented Generation) + GPT-4

**Функционал:**
- Студент задает вопрос по материалу курса
- AI ищет релевантную информацию в уроках
- Генерирует ответ на основе контента курса
- Ссылается на конкретные уроки

**Ограничения:**
- Не отвечает на вопросы вне контекста курса
- Не заменяет учителя для сложных вопросов
- Предлагает "Задать вопрос учителю" если не уверен в ответе

**UI:**
- Иконка чат-бота в правом нижнем углу
- Всплывающее окно чата
- История вопросов и ответов

#### 5.2.2 Персонализированные рекомендации

**AI анализирует прогресс студента:**
- Какие темы даются легко, какие сложно
- Какие типы заданий предпочитает
- Оптимальное время для учебы

**Рекомендации:**
- "Рекомендуем повторить урок 5 - вы получили низкий балл за тест"
- "Вы хорошо справляетесь с текстовыми заданиями, попробуйте больше голосовых"
- "Ваша активность выше по вечерам - запланируйте повторение на 19:00"

#### 5.2.3 Адаптивные тесты

**Концепция:** Сложность вопросов подстраивается под уровень студента.

**Алгоритм:**
- Начинаем со среднего уровня сложности
- Если студент отвечает правильно → следующий вопрос сложнее
- Если неправильно → следующий вопрос проще
- Итоговая оценка учитывает сложность вопросов

**Модели данных:**

```prisma
model QuizQuestion {
  // существующие поля...
  difficulty Int @default(5)  // 1-10, где 10 - самый сложный
}

model AdaptiveQuizSession {
  id          String   @id @default(uuid())
  userId      String
  user        User     @relation(fields: [userId], references: [id])

  quizId      String
  quiz        LessonQuiz @relation(fields: [quizId], references: [id])

  currentDifficulty Int @default(5)
  questionsAnswered Int @default(0)
  correctAnswers    Int @default(0)

  estimatedLevel    Float?  // оценка уровня студента

  completedAt DateTime?
  createdAt   DateTime @default(now())
}
```

### Приоритет 5.3: Автоматизация рутины

#### 5.3.1 Автоматические напоминания

**Триггеры:**
- ДЗ не сдано за 24 часа до дедлайна → напоминание студенту
- Студент не заходил 3 дня → напоминание + уведомление учителю
- Урок через 1 час, студент не онлайн → push-уведомление

**Реализация:**
- Cron jobs или scheduled tasks
- Проверка условий каждый час
- Отправка уведомлений через существующую систему

#### 5.3.2 Автоматическая генерация отчетов

**Еженедельный отчет для учителя:**
- Посещаемость за неделю
- Сданные/несданные ДЗ
- Средний балл по тестам
- Активность студентов
- Рекомендации AI

**Ежемесячный отчет для студента:**
- Прогресс за месяц
- Достижения
- Сравнение с предыдущим месяцем
- Цели на следующий месяц

**Отчет для родителей (еженедельно):**
- Посещаемость ребенка
- Оценки
- Комментарии учителя
- Рекомендации

**Формат:** Email с PDF вложением

#### 5.3.3 Автоматическое создание расписания

**AI оптимизирует расписание:**
- Учитывает предпочтения учителя (доступные часы)
- Избегает конфликтов между потоками
- Равномерно распределяет нагрузку
- Учитывает часовые пояса студентов (если применимо)

**UI:**
- Кнопка "Сгенерировать расписание автоматически"
- Учитель может принять или отредактировать
