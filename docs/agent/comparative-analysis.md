# Сравнительный анализ Fatiha.ru с эталонными платформами (июнь 2026)

## 0. Контекст

Fatiha.ru — нишевая LMS исламского образования: живые уроки (Jitsi), домашние задания, тесты, чат, библиотека книг, расписание. Целевая аудитория — изучающие арабский язык, Коран, акыду, фикх.

Сравнение проведено с тремя категориями эталонов:
- **Универсальные LMS:** Moodle, Canvas, Google Classroom
- **Русскоязычные edtech:** GetCourse, Skillbox, Stepik, Учи.ру
- **Нишевые (Коран/языки):** Duolingo, Quranly, Tarteel, Preply, Khan Academy

---

## 1. Онбординг и быстрый старт

### Что есть в Fatiha
- Контекст `OnboardingProvider` в `layout.tsx` — скелет с тултипами, но **UI-рендера нет** (контекст готов, тултипы не реализованы).
- Страница «Информация» у учителя и студента — пассивный текст.
- **Критическая проблема:** нет самостоятельной записи на курс из каталога — ученик должен ждать приглашения от учителя (или вводить токен). Для нового ученика это 2-3 дня ожидания.

### Как делают эталоны
- **Google Classroom** — вход через Google Account, ноль паролей, первый урок за 30 секунд.
- **Duolingo** — 2-минутный тест на уровень → выбор языка → первый урок сразу.
- **Preply** — описание целей → подбор репетитора → пробный урок за 3 клика.
- **Quranly** — регистрация → цель (1 мин/день) → сразу экран чтения Корана.

### Вывод
**Fatiha проигрывает всем.** Нет ни одного варианта входа без пароля, нет теста на уровень, нет пробного урока. Самостоятельная запись на курс работает, но завязана на ручное одобрение учителем (статус `PENDING_REVIEW`).

### Рекомендации
1. **Пробный урок** — кнопка «Записаться на пробный урок» на карточке курса (отдельный статус `TRIAL_ATTEMPTED`, авто-одобрение).
2. **Онбординг-тур** — дописать UI поверх существующего `OnboardingProvider`: 3 шага (выбери курс → получи ссылку → начни урок).
3. **Быстрая регистрация** — опция входа через Google/Telegram (NextAuth уже поддерживает OAuth-провайдеры).

## 2. Каталог и самостоятельная запись

### Что есть в Fatiha
- Каталог `/courses` — есть. Карточки с описанием, учителем, расписанием.
- Форма записи `/courses/[streamId]/apply` — есть, с проверками (гендер, ёмкость, дедлайн).
- **Но:** после заявки — ручное одобрение учителем, потом оплата, только потом запись.
- Приглашение по токену (`/join/[token]`) — мгновенная запись, но токен знает только учитель.

### Как делают эталоны
- **Stepik** — каталог с фильтрами → один клик «Начать» → доступ к контенту мгновенно.
- **Preply** — профили преподавателей с отзывами, рейтингом, ценами → запись на пробный урок бесплатно.
- **Uchi.ru** — тест на уровень → подбор курса → мгновенный доступ.

### Вывод
Каталог есть, но воронка записи **слишком длинная**: заявка → ожидание → оплата → одобрение. Для конверсии критично добавить **пробный урок без оплаты** и **авто-одобрение** для открытых потоков.

## 3. Геймификация и удержание

### Что есть в Fatiha
- Минимальная: счётчик дней, базовая статистика посещаемости.
- Нет стриков, нет мотивации возвращаться.
- **Баг:** прогресс студента часто 0/0 (см. ниже), что убивает мотивацию.

### Как делают эталоны
- **Duolingo** — стрики, лиги, XP, бейджи, milestone-анимации, streak-freeze. Ключевой инсайт: при стрике 7+ дней вероятность завершения курса растёт в 3.6 раза.
- **Quranly** — адаптация Duolingo для Корана: **хасанаты вместо XP**, стрик-трекер, конкурентные лидерборды среди друзей, еженедельный трекер чтения.
- **Tarteel** — ИИ-оценка чтения, трекинг запоминания с таймингами.
- **Учи.ру** — адаптивная сложность, анимированные награды.

### Вывод
**Критический пробел.** Геймификация — основной драйвер повторных визитов в образовательных приложениях. Без неё студент забывает вернуться.

### Рекомендации (приоритезированно)
1. **Стрик-трекер** — дни подряд посещения/уроков. Самый простой эффект.
2. **Хасанаты** — виртуальная валюта за действия (урок = +10, домашка = +20, тест = +30). Религиозный контекст делает XP абсурдным.
3. **Лидерборды** — конкурентные группы среди однокурсников (не глобальные, а по потоку).
4. **Мотивационные уведомления** — «Али, вы пропустили 2 дня подряд — вернитесь к уроку».

## 4. Аналитика прогресса

### Что есть в Fatiha
- **Баг прогресса:** студент видит «Мои уроки» (2 урока), но «Мой прогресс» = 0/0 уроков, 0%. Причина: таблица `StudentProgress` инициализируется при первом действии (heartbeat, тест, домашка). Если студент только записан — прогресс 0/0.
- Аналитика учителя: посещаемость, время в кабинете, тесты на проверке. Но числа захардкожены (0 минут, 0%).
- **Нет прогнозирования оттока** (как в Moodle Learning Analytics).
- **Нет визуальных графиков** (трендов, прогресс-баров).

### Как делают эталоны
- **Moodle** — Learning Analytics: прогнозирует отток студентов.
- **Canvas** — real-time engagement analytics.
- **Khan Academy** — mastery learning: визуальные графики освоения тем.
- **GetCourse** — cross-platform analytics с синхронизацией платежей.

### Вывод
Аналитика учителя — на уровне «список с нулями». Аналитика студента — сломана (0/0).

### Рекомендации
1. **Фикс бага прогресса** — инициализировать `StudentProgress` при создании `Enrollment` (вместо отложенного создания).
2. **Графики прогресса** — Chart.js или Recharts: линейные графики посещаемости, прогресса по урокам.
3. **Уведомления об отставании** — автоматическое письмо учителю, если студент не заходил 7+ дней.

## 5. Монетизация

### Что есть в Fatiha
- Заявки на запись с ручным одобрением.
- Endpoint `claim-payment` (ручной флоу оплаты).
- Нет подписок, нет рекуррентных платежей, нет рассрочек.

### Как делают эталоны
- **GetCourse** — подписки, рекуррентные платежи, рассрочки, скидочные купоны.
- **Skillbox** — фиксированная стоимость программ, гарантия возврата.
- **Duolingo** — Freemium (Super, Max, Ads).
- **Preply** — почасовая оплата через платформу.

### Вывод
Монетизация примитивная. Ручной флоу оплаты — временное решение, неудобное для студента.

### Рекомендации
1. **Подписка на курс** — ежемесячный автоплатёж (Stripe/YooMoney).
2. **Рассрочка** — разбить стоимость курса на 3-6 месяцев.
3. **Пробный бесплатный период** — 7 дней доступа к курсу.

## 6. Библиотека (PDF → HTML)

### Что есть в Fatiha
- 4 книги: Коран (TEXT), Сахих аль-Бухари (TEXT), Мединский арабский т.1 (PDF), Муалим Сани (PDF).
- TEXT-книги рендерятся как **живой HTML** (аяты, переводы, таджвид-раскраска).
- PDF-книги — через `<object>` с кнопками «Открыть/Скачать». Никакого взаимодействия.
- Инфраструктура готова: `BookChapter.content` = JSON, `BookReader` умеет рендерить главы.

### Как делают эталоны
- **Quranly** — интерактивный экран чтения: трекинг времени, пройденных аятов, хасанатов, стрик-трекер на главной.
- **Tarteel** — ИИ-распознавание чтения Корана в реальном времени, тайминг, подсказки при забывании.
- **Khan Academy** — интерактивные упражнения вместо статичного текста.
- **Moodle Books** — встроенный конструктор электронных книг.

### Вывод
Библиотека — сильное место (текстовые книги уже красивые), но PDF-книги — тупик.

### Рекомендации (план миграции)
1. **Парсинг PDF** — использовать `pdf-parse` или `pdf.js` для извлечения текста из PDF.
2. **Разбивка на главы** — по оглавлению или автоматически (каждая новая страница = новая глава).
3. **Создание BookChapter** — для каждой главы: `content: { arabic, translation }` (или `{ verses: [...] }` для Корана).
4. **Перевод sourceType** — с `PDF` на `TEXT`.
5. **Добавление интерактивности** — подсветка аятов, переключение переводов, поиск по тексту.

## 8. План приоритетов на ближайшие месяцы

### Фаза 1 (1-2 недели) — Критичное
- Фикс бага прогресса 0/0 (2 часа)
- Стрик-трекер (2-3 дня)
- Хасанаты (2-3 дня)
- Пробный урок (1 день)
- Онбординг-тур поверх OnboardingProvider (1 день)

### Фаза 2 (2-4 недели) — Высокий приоритет
- Интерактивное чтение (подсветка аятов, тафсир)
- Графики прогресса (Recharts)
- Лидерборды по потоку
- Быстрая регистрация (Google/Telegram OAuth)

### Фаза 3 (1-2 месяца) — Средний
- Подписка на курс (Stripe/YooMoney)
- Прогнозирование оттока
- Сертификаты
- Миграция 1-2 PDF-книг в HTML

### Фаза 4 (долгосрочно)
- AI-распознавание чтения Корана (требует ML-команды)
- Маркетплейс курсов
- Персональный куратор

## 9. Культурная адаптация

Ключевой инсайт из анализа Quranly: **заменяйте игровые механики на религиозные**:
- XP → хасанаты (добрые дела)
- Лиги → конкурентные группы для чтения
- Достижения → добрые дела
- Push-уведомления → религиозные напоминания (время намаза, пятница)

Это не «фича», а **фундаментальный подход к UX**, который определяет, будет ли платформа чувствовать себя «своей» для целевой аудитории.
