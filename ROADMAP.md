# План развития Fatiha.ru LMS

## 📋 Навигация

Этот план разбит на 3 документа для удобства работы:

1. **[ROADMAP_PART1.md](./ROADMAP_PART1.md)** - Текущее состояние + Этап 1
   - Анализ текущего состояния проекта
   - **Этап 1:** Административная панель и коммуникация (3-4 недели)
     - Админ панель и модерация
     - Система уведомлений (email + in-app)
     - Чат и мессенджер (WebSockets)
     - Гендерное разделение

2. **[ROADMAP_PART2.md](./ROADMAP_PART2.md)** - Этапы 2-3
   - **Этап 2:** Контент и вовлеченность (3-4 недели)
     - Записи уроков (Jibri)
     - Прогресс студента и геймификация
     - Мобильная оптимизация и PWA
   - **Этап 3:** Монетизация и масштабирование (4-6 недель)
     - Система оплаты (ЮКасса)
     - Сертификаты
     - Redis, BullMQ, PgBouncer
     - Собственный Jitsi сервер

3. **[ROADMAP_PART3.md](./ROADMAP_PART3.md)** - Этапы 4-5
   - **Этап 4:** Специфика исламского образования (6-8 недель)
     - Родительский кабинет
     - Инструменты для изучения Корана (таджвид, хифз)
     - Многоязычность (RTL для арабского)
     - Система иджаз
   - **Этап 5:** AI и автоматизация (8-12 недель)
     - AI для учителя (генерация тестов, автопроверка)
     - AI для студента (чат-бот, персонализация)
     - Автоматизация рутины

## ⚠️ Важные правила для разработки

### Для агентов и разработчиков:

1. **Последовательность обязательна**
   - Работайте строго по порядку: Этап 1 → 2 → 3 → 4 → 5
   - Не начинайте новый этап, пока не завершен предыдущий
   - Каждый этап имеет четкие критерии завершения

2. **Фокус на текущем этапе**
   - Читайте только документ текущего этапа
   - Не пытайтесь реализовать функционал из будущих этапов
   - Если что-то из будущего этапа кажется нужным сейчас - сначала завершите текущий

3. **Качество важнее скорости**
   - Пишите тесты для нового функционала (цель: >70% покрытие)
   - Обновляйте документацию (CLAUDE.md, PROJECT.md)
   - Создавайте миграции БД (не используйте db push)
   - Проверяйте безопасность (rate limiting, валидация, права доступа)

4. **Критерии завершения этапа**
   - В конце каждого документа есть чек-лист критериев
   - Все пункты должны быть выполнены перед переходом к следующему этапу
   - Если критерий не выполнен - этап не завершен

## 💡 Рекомендации

### Технологический стек (дополнения к текущему):

**Этап 1:**
- Socket.io для WebSockets
- Nodemailer или SendGrid для email
- Zod для валидации (уже есть)

**Этап 2:**
- Jibri для записи Jitsi
- FFmpeg для обработки видео
- Workbox для PWA

**Этап 3:**
- ЮКасса SDK для оплаты
- PDFKit для сертификатов
- Redis + ioredis
- BullMQ для очередей

**Этап 4:**
- next-intl для i18n
- Quran.com API (опционально)

**Этап 5:**
- OpenAI API (GPT-4, Whisper)
- LangChain для RAG (опционально)

### Безопасность:

- ✅ Все API маршруты защищены аутентификацией
- ✅ Rate limiting на всех endpoints (уже реализовано)
- ✅ Валидация входных данных через Zod (частично реализовано)
- ✅ CSRF protection для форм
- ✅ XSS protection (React автоматически)
- ✅ SQL injection protection (Prisma автоматически)

### Производительность:

- ✅ Используйте React.lazy для code splitting
- ✅ Оптимизируйте изображения (Next.js Image)
- ✅ Кэшируйте статику (Redis в Этапе 3)
- ✅ Используйте ISR для публичных страниц
- ✅ Мониторьте bundle size
