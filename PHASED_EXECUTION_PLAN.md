## 🚨 ЭТАП 1: Критические Баги Навигации (Первоочередно)

### Цель
Разблокировать базовую навигацию для всех ролей пользователей.

### Проблемы для решения
1. ❌ Сайдбары не реагируют на клики (студент, админ, учитель)
2. ❌ Невидимый туториал блокирует весь экран после входа
3. ❌ Двойная шапка на главной странице
4. ❌ Админа редиректит на `/teacher` вместо `/admin`

### Файлы для редактирования

#### 1.1. Починка SPA-роутинга в сайдбарах
```
src/components/dashboard/StudentSidebar.tsx
src/components/dashboard/AdminSidebar.tsx
src/components/dashboard/TeacherSidebar.tsx
```

**Действия:**
- Найти все элементы навигации (`<div>`, `<a>`, `<button>`)
- Заменить на `<Link>` из `next/link`
- Убедиться что `href` указан правильно
- Удалить `onClick` с `window.location.href`

**Пример замены:**
```tsx
// ❌ Было
<div onClick={() => window.location.href = '/student/lessons'}>
  Мои уроки
</div>

// ✅ Должно быть
<Link href="/student/lessons" className="...">
  Мои уроки
</Link>
```

#### 1.2. Удаление невидимого туториала
```
src/app/layout.tsx
src/app/(dashboard)/layout.tsx
src/components/Onboarding.tsx (если существует)
src/components/Tutorial.tsx (если существует)
```

**Действия:**
- Найти компонент с `className="fixed inset-0 bg-black/50"` и `z-index: 9998`
- Закомментировать или удалить полностью
- Проверить глобальные провайдеры в layout.tsx

#### 1.3. Удаление двойной шапки на главной
```
src/app/layout.tsx
src/components/layout/Header.tsx
src/components/layout/TopBar.tsx (если существует)
```

**Действия:**
- Найти два компонента шапки (вероятно `<TopBar />` и `<MainNavbar />`)
- Удалить верхнюю ненужную шапку
- Оставить только красивую нижнюю панель с логотипом

#### 1.4. Исправление редиректа админа
```
src/app/api/auth/[...nextauth]/route.ts
src/middleware.ts
```

**Действия:**
- В NextAuth callbacks добавить проверку роли:
```typescript
callbacks: {
  async redirect({ url, baseUrl, token }) {
    if (token?.role === 'ADMIN') return `${baseUrl}/admin`;
    if (token?.role === 'TEACHER') return `${baseUrl}/teacher`;
    if (token?.role === 'STUDENT') return `${baseUrl}/student`;
    return baseUrl;
  }
}
```

### Критерии завершения Этапа 1
- [ ] Все ссылки в сайдбарах работают без перезагрузки страницы
- [ ] Невидимый туториал больше не появляется
- [ ] На главной странице только одна шапка
- [ ] Админ после входа попадает на `/admin`

## 🏗️ ЭТАП 2: Разделение Layout и Headers

### Цель
Изолировать интерфейсы разных ролей и создать динамическую навигацию.

### Проблемы для решения
1. ❌ В админ-панели показывается шапка "Teacher Portal"
2. ❌ Шапка не меняется в зависимости от статуса пользователя
3. ❌ Нет разделения между layout'ами дашбордов

### Файлы для создания/редактирования

#### 2.1. Создание отдельных компонентов Headers
```
src/components/dashboard/AdminHeader.tsx (создать новый)
src/components/dashboard/TeacherHeader.tsx (создать новый)
src/components/layout/MainNavbar.tsx (отредактировать)
```

**AdminHeader.tsx** - должен содержать:
- Логотип Fatiha.ru
- Навигация: Дашборд, Пользователи, Курсы, Заявки учителей
- Профиль админа + выход

**TeacherHeader.tsx** - должен содержать:
- Логотип Fatiha.ru
- Навигация: Мои курсы, Расписание, Чат, Уведомления
- Профиль учителя + выход

#### 2.2. Обновление Layout файлов
```
src/app/(dashboard)/admin/layout.tsx
src/app/(dashboard)/teacher/layout.tsx
src/app/(dashboard)/student/layout.tsx
```

**Действия:**
- В `admin/layout.tsx` импортировать `AdminHeader`
- В `teacher/layout.tsx` импортировать `TeacherHeader`
- Убедиться что компоненты не наследуют неправильный header

#### 2.3. Динамическая навигация на главной
```
src/components/layout/MainNavbar.tsx
```

**Действия:**
- Добавить проверку сессии:
```tsx
import { useSession } from "next-auth/react";

const { data: session } = useSession();

// Если нет сессии -> кнопка "Войти"
// Если есть сессия -> аватарка + ссылка на кабинет
```

### Критерии завершения Этапа 2
- [ ] Админ видит AdminHeader в `/admin`
- [ ] Учитель видит TeacherHeader в `/teacher`
- [ ] На главной странице кнопка меняется: "Войти" → "Кабинет"
- [ ] Нет пересечения компонентов между ролями

## 🔧 ЭТАП 3: Исправление API и Загрузки Данных

### Цель
Устранить бесконечные загрузки и восстановить сломанные страницы.

### Проблемы для решения
1. ❌ Страница `/admin/users` сломана (желтое предупреждение)
2. ❌ Бесконечная загрузка в разделах "Курсы", "Уведомления"
3. ❌ Битые изображения (не загружаются фото профилей/курсов)

### Файлы для редактирования

#### 3.1. Восстановление страницы управления пользователями
```
src/app/(dashboard)/admin/users/page.tsx
src/app/api/admin/users/route.ts
```

**Действия:**
- Проверить API endpoint `/api/admin/users`
- Убедиться что Prisma запрос возвращает данные
- Добавить обработку ошибок и пустых состояний
- Исправить таблицу пользователей на фронтенде

#### 3.2. Исправление бесконечных загрузок
```
src/app/(dashboard)/teacher/courses/page.tsx
src/app/(dashboard)/admin/courses/page.tsx
src/app/(dashboard)/teacher/notifications/page.tsx
```

**Действия:**
- Добавить `try-catch` в API вызовы
- Реализовать fallback для пустых данных:
```tsx
{courses.length === 0 ? (
  <EmptyState
    title="Курсов пока нет"
    action="Создать первый курс"
  />
) : (
  <CoursesList courses={courses} />
)}
```

#### 3.3. Починка загрузки изображений
```
src/app/api/upload/route.ts
src/lib/s3.ts (если используется S3)
```

**Действия:**
- Проверить что S3/storage правильно настроен
- Убедиться что `imageUrl` корректно возвращается
- Проверить что URL записывается в базу Prisma
- Добавить fallback изображения для битых ссылок

### Критерии завершения Этапа 3
- [ ] Страница `/admin/users` показывает таблицу пользователей
- [ ] Нет бесконечных спиннеров загрузки
- [ ] Изображения профилей и курсов загружаются корректно
- [ ] Пустые состояния показывают понятные сообщения

## 🎨 ЭТАП 4: UI/UX Полировка и Мобильная Версия

### Цель
Улучшить визуальную привлекательность и адаптивность.

### Проблемы для решения
1. 🟡 Базовые иконки выглядят "дешево"
2. 🟡 Стандартные шрифты делают интерфейс шаблонным
3. 🟡 Мобильная версия сломана (двойной гамбургер, наложения)
4. 🟡 Несогласованность layout'ов (узкие vs широкие контейнеры)

### Файлы для редактирования

#### 4.1. Обновление типографики
```
src/app/layout.tsx
tailwind.config.ts
```

**Действия:**
- Добавить Google Fonts в `layout.tsx`:
```tsx
import { Plus_Jakarta_Sans } from 'next/font/google';

const jakarta = Plus_Jakarta_Sans({
  subsets: ['latin', 'cyrillic'],
  weight: ['400', '500', '600', '700']
});
```
- Обновить `tailwind.config.ts`:
```js
theme: {
  extend: {
    fontFamily: {
      sans: ['var(--font-jakarta)', 'system-ui', 'sans-serif'],
    }
  }
}
```

#### 4.2. Замена библиотеки иконок
```
package.json
src/components/**/*.tsx (все компоненты с иконками)
```

**Действия:**
- Установить: `npm install lucide-react`
- Заменить все старые иконки на Lucide:
```tsx
import { Home, Users, BookOpen } from 'lucide-react';

<Home className="w-5 h-5" />
```

#### 4.3. Исправление мобильной версии
```
src/components/dashboard/MobileMenu.tsx
src/components/dashboard/AdminHeader.tsx
src/components/dashboard/TeacherHeader.tsx
```

**Действия:**
- Убрать дублирующиеся кнопки гамбургера
- Добавить `z-index` правильно для мобильного меню
- Исправить наложение на текст приветствия
- Перестроить карточки статистики в колонку на мобилках:
```tsx
<div className="grid grid-cols-1 md:grid-cols-3 gap-4">
```

#### 4.4. Унификация layout контейнеров
```
src/app/(dashboard)/admin/page.tsx
src/app/(dashboard)/teacher/page.tsx
src/app/(dashboard)/student/page.tsx
```

**Действия:**
- Заменить все `max-w-5xl mx-auto` на `w-full px-8`
- Использовать full-width подход для дашбордов
- Оставить небольшие отступы для "дыхания"

### Критерии завершения Этапа 4
- [ ] Новый шрифт применен ко всему интерфейсу
- [ ] Все иконки заменены на Lucide React
- [ ] Мобильная версия работает без наложений
- [ ] Layout согласован (full-width с padding)
